- **Problema detectado:** Se ha identificado que GPSpedia no mantiene una comunicación funcional con el microservicio de administración. Este defecto debe tratarse como una prioridad alta porque puede afectar a las operaciones administrativas y a otras funcionalidades que dependan de dicho servicio.
- **Diagnóstico de la comunicación:** Inspecciona el flujo completo entre el cliente y el microservicio de administración. Determina la causa real del fallo revisando: URL y configuración del servicio, acciones y parámetros enviados, contratos de solicitud y respuesta, métodos HTTP y configuración de solicitudes, autenticación y autorización, manejo de errores, restricciones de acceso y configuración de despliegue, identificadores de acciones, nombres de funciones y rutas de ejecución, formato de los datos intercambiados, y dependencias entre los servicios y el cliente.
- **Recuperación del servicio:** Una vez identificada la causa, corrige los componentes necesarios para restablecer la comunicación. La solución debe garantizar que: las solicitudes lleguen al servicio correcto, las acciones reconocidas por el cliente existan en el backend correspondiente, los parámetros se interpreten correctamente, las respuestas mantengan el formato esperado, los errores del servicio se comuniquen de forma comprensible, los fallos de red no se presenten como respuestas válidas, los controles de acceso continúen funcionando, y las funciones administrativas recuperadas utilicen el servicio real y no respuestas simuladas. No introduzcas un segundo mecanismo administrativo paralelo para ocultar el problema.
- **Alcance de los cambios:** Modifica únicamente los componentes necesarios para recuperar la comunicación. Si es indispensable modificar un contrato compartido, identifica sus consumidores y conserva la compatibilidad con las funcionalidades existentes. No realices cambios indiscriminados en otros microservicios.
- **Criterios de finalización:** La comunicación debe verificarse mediante operaciones reales de lectura y, cuando corresponda, escritura, utilizando usuarios y permisos adecuados. No es suficiente comprobar que la URL responde o que el servicio puede abrirse. Debe comprobarse que las acciones administrativas requeridas funcionan correctamente de extremo a extremo.
